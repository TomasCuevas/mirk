# Reader 0.2.0

Objective: first-party PDF reader that opens, scrolls and remembers — the roadmap's read-only half. Branch: `feat/reader-0.2.0`.
Delivery: `auto-chain`, `chain_strategy=feature-branch-chain` (forecast: over 400 authored lines). Checks: Cargo and Bun/Vitest; real Tauri runtime where applicable.
Scope reduced by the owner in **L53**. The full history of the larger scope is in this document's Log and in `odd/0.2.0-state.md`.

## Specs

- S1 — "0.2.0"; roadmap `odd/roadmap.md`, F0: a first-party reader that opens a real PDF the library already holds and renders its pages. Unchanged by L53.
- S2 — **Reduced in L53.** 0.2.0 is the roadmap's read-only half (tracks T1–T3 of the roadmap: open, scroll, remember). Text layer, selection and find-in-document are **out** of this version, and so is the "Lector completo" wording that used to state them.
- S3 — "Ocupar la ventana": the reader takes over the window and hides the main navigation while reading. Unchanged (chosen in L2).
- S4 — Reading-session and page facts are recorded **from the reader only**, through the typed APIs already committed at `8ad053a` on `feat/reader-storage-slices`. No schema beyond V12 in this version, no identity-handle migration, and no capture from external viewers.
- S5 — **Non-goals for 0.2.0, explicitly.** No custom byte transport: the `reader_ipc` / `reader_serve` / `reader_session` / `reader_file` / `reader_budget` subsystem is archived, not finished (`odd/0.2.0-state.md` §4B1). No V13/V14 identity backfill. No per-document render budget, pathological-page policy, or memory-eviction optimisation beyond keeping the visible window bounded.
- S6 — A real document is the acceptance surface. A debug fixture, a synthetic page provider, or an embedded 1,207-byte PDF is not evidence that 0.2.0 works.

## Warnings paid for in this feature

- **A hidden window paints nothing.** `tauri.conf.json` declares the main window hidden so the stored size
  can be applied first, and nothing ever showed it. An unmapped window is a `0x0` webview with
  `document.hidden === true`; WebKit suspends `requestAnimationFrame`, and pdf.js paints pages in slices
  scheduled on it. The reader therefore parsed every page, laid out every page, and drew none — with no
  error in the console and none in the webview's error events. Fixed in `407f56d`; measured in L54.
- **A window applied before its canvases exist is remembered as a terminal failure.** Resuming wrote the
  scroll offset from inside one Svelte effect, and the window effect later in the **same** flush applied
  the resumed window before the `{#each}` slots — and their canvases — existed in the next one. `#draw`
  threw "page N has no canvas to draw into", `PageRenderSet` stored that as a failure nothing retried,
  and pages 3 to 6 stayed blank forever while page 1 drew because its canvases already existed. The
  resume was right and the page was empty, which no first-open measurement can catch.
- **A self-reported render is not a render.** The earlier effort's proof was a log line saying a page had
  rendered. What settled it here was reading the page view's own per-page state and the canvas's pixels,
  which is why `reader-measure` exists as a temporary harness rather than a permanent claim.

Three things were shared and are now separated, each by a mechanism rather than a habit: (1) **the library** — `DataProfile` is a property of the build, so a debug build resolves `mirk-dev` beside `mirk`, and it *refuses* an explicit `MIRK_DATA_DIR` that points at the production directory, naming what it will not open; (2) **the update channel** — the updater and process plugins are registered only by a production build, because a check from `tauri dev` reads the installed copy's endpoint and an install would replace the reader's application; (3) **the webview identity** — `tauri.dev.conf.json` overrides the identifier for `bun run app:dev`, so cache and storage go to `dev.mirk.desktop.dev`. Proven by running the dev build and comparing: the production database's sha256 and mtime unchanged, `dev.mirk.desktop` mtime unchanged, `mirk-dev/mirk.sqlite3` created, and the application reporting "the library has no enabled folder to watch" — an empty library, not the reader's.

L62 — The owner answered the two release questions L60/L61 left open. (a) **No automatic backup before a migration**: the upgrade's single transaction is the protection it relies on, and it stays that way. The guarantee is exactly what the tests pin — a step that fails inside the transaction takes the whole upgrade back to the version it started from, and two openers racing migrate once (`a_failed_late_step_rolls_the_whole_upgrade_back`, `two_openers_at_once_migrate_an_old_database_exactly_once`, `the_upgraded_genuine_version_11_database_reopens_without_losing_a_row`). (b) **The owner's real library stays at schema 13** — it is readable by the 0.2.0 line, and the hand-taken `mirk.sqlite3.pre-v13-20261105T141142` stays beside it as their own copy. L63 — R3b built to L4's rule rather than to a guess about it. The clock is a module with no store, no IPC and no DOM (`reader-session.ts`), because the twenty minutes must be provable in a millisecond: the idle pause lands at `last interaction + 20 min` — not at the moment the reader happens to touch the keyboard again — so somebody who returns after an hour contributes the twenty minutes before the pause and nothing in between. Visibility and focus are read from the window itself on every event; the session starts inactive, so an application nobody showed records no reading it did not do. Page visits are recorded per page, collapsing the page already on screen and recording a return as a new visit, and each carries the visible time it spent on screen, so a session's visits never sum past its `activeMs`.

The write is one command at the end (`reader_record_session`), not one per page, because `page_visits` names its session through `(session_id, doc_id)` and a visit cannot exist before the session it happened in. Every fact is checked **before** anything is written: a session whose third visit is impossible stores nothing rather than a session and two visits. A session with no page turned is still recorded — the reader sat with the book open, and that is reading. A failed write is swallowed exactly as a failed page write is, and for the same reason: closing a book must not be interrupted by bookkeeping, and there is no retry queue to feed.

The unit is not done until a real document says so. `reader_record_session` has never been called by a running application holding a real PDF, so the number R4 has to produce is a session row with a non-zero `active_ms` and the visits the reader actually showed (S6).

L72 — The owner's suspicion was the right one: the integrated reader's writes and the launch sweep's re-recording of what the external viewer last did were fighting, and the card lost. Not a lock, a **ranking**: `library()` picked the progress row with the greatest **id** — the row written last — so a sweep that re-recorded an older external page after the reader had written page 20 made the card fall back to page 3, while the reader resumed from page 20. The percentage said one thing and the document opened at another, which is exactly what the owner described.

The rule is now the one the sections already documented: the newest **reading**, and a row that says *when it was read* outranks one that only says when it was written. The first attempt ordered by `COALESCE(read_at, updated_at)` and a sweep test caught it at once: an old row without an instant has a *newer* write time than a reading from last year, and the sweep then re-recorded a position it had already stored. Ordering is `(read_at IS NULL) ASC, COALESCE(read_at, updated_at) DESC, id DESC`. A row with an observation instant is ranked by when the reading happened; a row without one (a position typed by hand) is ranked by when it was written, which is when the reader acted. A store test pins the collision: a native page 20 at t=2000 followed by an external page 3 at t=1000 answers page 20, native.

L73 — The owner's decision, and the rule that follows: **the newest observation wins, whichever source made it**. Verified before implementing, in the owner's own database: for three of four documents the library's winner was an `evince-gvfs` row carrying **exactly** the native row's `read_at`, so the tie was settled by row id and the older page won the card while the reader resumed from the newer one. A viewer cannot have read in the same second as the reader: the instant was inherited by the sweep (`with_swept_reading_time`).

Three changes, each one rule rather than a patch:

1. **A source may only claim the instant it observed.** The sweep no longer takes the maximum of the stored time and the history's. A source that cannot say when cannot claim where either — an undated row can never answer "where is this document" and would only grow the log — with the one exception kept: an undated position is still recorded while nothing dated answers, which preserves discovery for a library no viewer ever dated. A stored time in the future still cannot block a credible observation.
2. **One selector.** `reader_position` no longer prefers the last `native` row; it asks `Store::library`, the same rule the card reads. Card and resume can no longer disagree, which is the whole point of the owner's phrase "no hay un único punto de la verdad".
3. **Ties go to the row that claimed the instant first.** Within one instant, `id ASC` — and that single character is what defeats the legacy rows already in the database: the row that observed the time wrote before the row that borrowed it. Undated rows keep `id DESC`, because among them the last written is the only evidence there is.

Tests: `a_reading_time_never_moves_backwards` became `a_swept_observation_keeps_only_its_own_instant`; `the_sweep_ignores_a_reading_time_in_the_future` now expects one recorded row instead of two, and the undated observation of a document with a dated reading is not news; `the_reader_resumes_at_the_page_it_recorded_not_the_external_viewers` became `the_reader_resumes_where_the_newest_reading_is_whoever_made_it`; and two new tests pin the legacy tie in the store and the borrowed-instant row in the library. Store 29 + 109, desktop 136, web 660, strict Clippy clean.

Not done, and out of 0.2.0: making the external viewer *open* at mirk's page. mirk now agrees with itself; a viewer agreeing with mirk is platform work with its own verification.

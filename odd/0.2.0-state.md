## 1. Bottom line

After the whole 0.2.0 effort, the feature branch has **no commits of its own**, **no closed task**, and
**no PDF rendered by the application**. What it has is roughly **19,200 uncommitted lines** — about
**12,750 of them production code** — spread over the working tree and ten worktrees, of which the
largest single subsystem (a defensive byte-transport, 6,748 lines of Rust) is **not registered in the
application at all**.

The work is not broken: every check in the main worktree passes today (§3). The work is *unfinished,
unintegrated, and out of proportion* with the feature it serves.

The failure was not rigor. It was **architecture**: the implementation chose a design that manufactured
risk (a byte server with its own threat model), and then the full weight of the high-risk process —
writer, independent verifier, correction, re-verification — was applied to that manufactured risk with
no exit criterion. Fifty-two log entries, 47 independent verifier rounds, nothing shipped.

## 5. Why it stalled — the mechanism

Worth recording, because it repeats if it is not named.

1. **The architecture manufactured the risk.** `reader_session.rs` protects against a local process
   swapping a PDF between the library record and the read — that is, against an adversary on a machine
   whose owner added the file to their own library. In this product that adversary does not exist. But
   because file access *looks* like a security surface, the design correctly triggered the high-risk
   path (independent verification), which then ran for dozens of rounds.
2. **The standard path was never measured first.** The project is Tauri 2 with no `assetProtocol` and
   no `tauri-plugin-fs` in `crates/mirk-desktop/capabilities/main.json`. Tauri's asset protocol already
   answers `Range`, which is exactly what pdf.js needs. Twenty minutes of measurement would have
   decided the transport before 6,748 lines were written.
3. **No exit criterion.** Each verification found something (they always find something) and nothing
   defined which findings were acceptable. The implied threshold became "zero findings", which does not
   exist. Hence 47 verifier rounds and 52 log entries.
4. **Worktrees replaced a source of truth.** Ten drafts under a gitignored directory, copied to each
   other as patches. Progress could not be committed because nothing was ever "accepted".

The owner pushed three times to stop the treadmill (`L23`, `L40`, `L41`, `L43`). Each time the agent
changed worktree and continued the same loop. That is a process defect, not an attitude problem.

## 6. Risk register

1. **Everything under `target/` is a single copy.** 9.2 GB of drafts in a gitignored directory. A
   `cargo clean`, a disk cleanup or a bad `git worktree prune` destroys work that has no commit
   anywhere. This is the highest-priority item in this document.
2. **The plan is untracked.** `odd/roadmap.md` and `odd/tasks/reader.md` are not in git. The reasoning
   that produced 0.2.0's order exists only in the filesystem.
3. **The feature branch equals `main`.** `feat/reader-0.2.0` at `26eeead` carries no signal; a reader
   looking for 0.2.0 finds nothing.
4. **Divergence.** The store changes in the working tree (§B3) and the V13/V14 drafts in the worktrees
   (§4C) are the same lineage evolving in parallel. Reconciling later costs more than choosing now.
5. **Unreviewed isolation claim.** The log repeatedly notes writes outside the project by workers
   (`/tmp/*`, `/dev/shm/*`). This assessment did not read or remove any of them.

## 7. Recommendation

**Keep.** The roadmap (§ `odd/roadmap.md`, unchanged). The four commits in §4A. The geometry and
presentation layer in §B2. The prep refactor in `target/reader-identity-prep`.

**Archive, do not delete.** The transport subsystem (§B1), the fixture harness (§B2), and the eight
superseded store drafts (§4C) — each on its own branch with a short README saying what it was meant to
solve and what was never proven. They become evidence for a future decision, not a debt.

**Concretely, in this order:**

1. Commit `odd/roadmap.md`, `odd/tasks/reader.md` and this document, so the plan exists in git.
2. Fast-forward `feat/reader-0.2.0` to `feat/reader-storage-slices` (4 commits, 0 conflicts expected —
   the feature branch has no commits of its own). The branch acquires its first real content.
3. Preserve before cleaning: commit the ten worktree drafts to their branches as-is, or at minimum make
   a bundle. Do this **before** any `cargo clean`.
4. Move the archive: `archive/reader-transport-defense` (the 7,523 Rust lines + fixture harness) and
   `archive/reader-identity-v14` (the `reader-doc-identity` draft), each with a README.
5. Reduce 0.2.0 to **"open a real PDF, scroll it, remember the page"** — the roadmap's T1+T2 without the
   custom transport. Measure `asset://` + pdf.js against the 136 MB book inside the real app first;
   decide the transport from that number.
6. Re-wire `reader-pages.ts` / `ReaderPages.svelte` to real pdf.js pages through the existing
   `RangeReader` boundary, and connect the reader to `App.svelte`.
7. Then, and only then, revisit session identity — with a demonstrated failure, not a hypothesised one.
